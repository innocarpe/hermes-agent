# TemperStone HQ Discord 채널 라우팅 1-pager

## 목적
이 문서는 **요청이 들어왔을 때 어디로 보낼지**를 빠르게 정하기 위한 운영 기준이다.

## 기본 원칙
- **Discord는 입구**다.
- **Hermes HQ는 SSOT**다.
- **채널은 역할별로 분리**한다.
- **문제의 성격이 다르면 채널도 다르게 보낸다.**
- **스타일보다 분류가 먼저**다.

## 라우팅 기준

### 1) 어디서 시작하나
- 새 시장/큰 방향/우선순위 → `01-전략`
- 제품 범위/기능/로드맵 → `02-제품`
- 콘텐츠 초안/발행/피드백 → `03-콘텐츠`
- 채널 구조/계정 구조/배포 설계 → `04-채널`
- 자동화/장애/cron/gateway/반복 작업 → `05-운영`
- 돈/정산/수익성/세금 → `06-재무`
- 완료된 일의 복기 → `07-회고`
- 톤/네이밍/브랜딩 → `08-브랜딩`
- 종료/보관 → `09-아카이브`

### 2) 어디로 넘기나
- **전략 판단**이 필요하면 `01-전략`
- **제품 결정**이 필요하면 `02-제품`
- **콘텐츠 생산**이 필요하면 `03-콘텐츠`
- **채널 구조와 분배**가 필요하면 `04-채널`
- **시스템/운영 이슈**면 `05-운영`
- **재무 판단**이면 `06-재무`
- **복기/교훈**이면 `07-회고`
- **브랜딩 문구**면 `08-브랜딩`
- **종료 처리**면 `09-아카이브`

### 3) thread를 만들지 말지
- `01-전략`: no thread
- `04-채널`: no thread
- `06-재무`: no thread
- `07-회고`: no thread
- `09-아카이브`: no thread
- 나머지 작업 채널은 기본적으로 thread를 허용한다

### 4) mention이 필요한가
- 전략/운영/제품/콘텐츠 작업 채널은 기본적으로 free response로 둔다
- 다만 리뷰가 길어지면 thread로 분리하고, 결정만 본문에 남긴다

### 5) 어떤 skill/workflow를 붙이나
- `01-전략` → `bd-intake`
- `02-제품` → `bd-review`
- `05-운영` → `hq-ops`
- `06-재무` → `finance-review`
- `07-회고` → `review-loop`
- `08-브랜딩` → `brand-review`
- `04-채널` → 기본 skill 없음, 구조가 안정화되면 별도 workflow를 붙인다

## 라우팅 예시
- “이 아이디어 할까?” → `01-전략`
- “이 기능 넣을까?” → `02-제품`
- “이 글 초안 봐줘” → `03-콘텐츠`
- “이 계정 구조 어떻게 나눌까?” → `04-채널`
- “봇이 왜 멈췄지?” → `05-운영`
- “이게 돈이 되나?” → `06-재무`
- “지난번 결정 왜 바뀌었지?” → `07-회고`
- “이름/톤 어때?” → `08-브랜딩`

## 운영 체크
- 요청이 섞여 있으면 **가장 먼저 결정해야 하는 축**을 기준으로 보낸다.
- 2개 이상 채널이 필요한 경우, **입구 채널에서 분해**한 뒤 각각 넘긴다.
- 라우팅 결과는 decision log에 남긴다.
- 채널 토픽은 설명이 아니라 **운영 계약**처럼 쓴다.
- YouTube/콘텐츠 채널의 세부 판정은 `docs/hq/discord-channel-youtube-routing-checklist.md`를 따른다.
