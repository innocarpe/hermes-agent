# First App Revenue Playbook — MVP Implementation Tickets

## 목적
MVP를 실제로 만들 수 있도록, 전체 흐름을 **작은 구현 티켓 7개**로 쪼갠다.

## 전제
- 대상은 `사진 → 보고서 / 문서화 앱`
- 범위는 1개월 MVP
- 먼저 핵심 흐름, 그다음 상태/예외, 마지막에 수익화 경계를 본다
- 이 티켓은 **반복 비용이 큰 워크플로**를 기준으로 정렬한다
- 수익화는 **누가 돈을 내는지**가 먼저 보이도록 설계한다
- 자세한 판정 기준은 `docs/hq/first-app-strategy-principles.md`를 따른다.

---

## Ticket 1 — MVP 범위 고정

**목표:** 타깃 사용자와 핵심 시나리오를 하나로 고정한다.

**결정된 타깃:** 소규모 시설 유지보수 / 현장 점검 팀

구체적으로는:
- 빌딩 / 상가 / 다세대 주택 관리 보조
- 시설 유지보수 담당자
- 점검 결과를 사진과 메모로 남겨야 하는 소규모 팀

**참조 문서**
- `docs/hq/first-app-revenue-scope-fixed.md`

**해야 할 일**
- 타깃을 1개만 선택
- 핵심 사용 시나리오 1개 정의
- MVP에서 제외할 기능 적기
- 성공 기준 3개 정의

**산출물**
- 타깃 1개
- 핵심 시나리오 1개
- 제외 리스트
- 성공 기준

**완료 기준**
- 이 문서를 보면 "누구를 위한 앱인지" 10초 안에 설명 가능해야 함

---

## Ticket 2 — 화면 흐름 고정

**목표:** 앱의 전체 흐름을 한 줄로 고정한다.

**참조 문서**
- `docs/hq/first-app-revenue-flow-map.md`
- `docs/hq/first-app-revenue-first-screen-wireframe.md`
- `docs/hq/first-app-revenue-photo-add-wireframe.md`
- `docs/hq/first-app-revenue-photo-note-wireframe.md`
- `docs/hq/first-app-revenue-template-selection-wireframe.md`
- `docs/hq/first-app-revenue-preview-pdf-wireframe.md`

**해야 할 일**
- 첫 화면 → 사진 추가 → 메모 → 템플릿 → 미리보기 → 공유 흐름 확인
- 각 단계의 목적 1문장씩 적기
- 각 단계에서 사용자가 해야 할 행동 1개씩 적기

**산출물**
- 최종 플로우 다이어그램
- 각 단계 역할 요약

**완료 기준**
- 흐름을 보고도 다음 화면이 무엇인지 바로 말할 수 있어야 함

---

## Ticket 3 — 첫 화면 구현

**목표:** 사용자가 새 보고서를 바로 시작하게 만든다.

**해야 할 일**
- 핵심 가치 문구 1개 배치
- `+ 새 보고서 시작` 버튼 배치
- 최근 보고서 2~3개 배치
- 템플릿 진입점 1개 배치

**산출물**
- 첫 화면 와이어프레임 또는 실제 화면

**완료 기준**
- 사용자가 첫 화면에서 무엇을 눌러야 하는지 즉시 알 수 있어야 함

---

## Ticket 4 — 사진 추가 + 메모 입력 구현

**목표:** 사진과 짧은 메모를 가장 적은 마찰로 입력하게 만든다.

**해야 할 일**
- 카메라로 찍기 / 갤러리에서 선택 버튼
- 썸네일 목록 표시
- 사진별 메모 한 줄 입력
- 상태 태그 3개 이하 선택
- 이전 / 다음 이동

**산출물**
- 사진 추가 화면
- 사진 메모 입력 화면

**완료 기준**
- 사진 여러 장을 넣고 각 장에 짧은 메모를 붙이는 흐름이 자연스러워야 함

---

## Ticket 5 — 템플릿 선택 구현

**목표:** 사용자가 보고서 형식을 오래 고민하지 않게 만든다.

**해야 할 일**
- 템플릿 2~3개만 노출
- 각 템플릿 한 줄 설명 추가
- 기본 선택값 1개 지정
- 미리보기 / 계속 버튼 연결

**산출물**
- 템플릿 선택 화면
- 템플릿별 간단 설명

**완료 기준**
- 사용자가 10초 안에 템플릿을 고를 수 있어야 함

---

## Ticket 6 — 미리보기 / PDF / 공유 구현

**목표:** 결과를 바로 문서처럼 보여주고 내보내게 만든다.

**해야 할 일**
- 보고서 미리보기 화면
- 제목 / 날짜 / 상태 요약 / 사진 / 메모 표시
- PDF 내보내기 버튼
- 공유하기 버튼
- 실패 상태 3~4개 정의

**산출물**
- 미리보기 화면
- PDF 내보내기 동작
- 공유 동작

**완료 기준**
- 결과물을 실제 업무 문서처럼 볼 수 있어야 함

---

## Ticket 7 — 상태값 / 예외 / 출시 판단

**목표:** MVP가 실제로 버틸 수 있는지 확인한다.

**해야 할 일**
- loading / empty / error 상태 정리
- 저장 권한 없음 / PDF 생성 실패 / 사진 누락 처리
- 내부 테스트 질문 리스트 작성
- GO / HOLD / NO-GO 기준 정의

**산출물**
- 상태표
- 예외 처리표
- 출시 판단표

**완료 기준**
- 핵심 흐름 외의 실패 지점이 문서화돼 있어야 함

---

## 추천 실행 순서
1. Ticket 1 — 범위 고정
2. Ticket 2 — 흐름 고정
3. Ticket 3 — 첫 화면
4. Ticket 4 — 사진 + 메모
5. Ticket 5 — 템플릿
6. Ticket 6 — 미리보기 / PDF / 공유
7. Ticket 7 — 상태 / 예외 / 판단

## 메모
- 이 7개 티켓은 기능 목록이 아니라 **검증 순서**다.
- 기능을 많이 넣는 것보다, 핵심 흐름이 끊기지 않는 게 더 중요하다.
