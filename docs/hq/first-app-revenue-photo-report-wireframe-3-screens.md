# First App Revenue — Photo-to-Report Wireframe (First 3 Screens)

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
`사진 → 보고서 생성` 앱의 핵심 UX를 가장 먼저 필요한 3개 화면으로 축약해, Stitch / Pencil MCP / Figma / Claude Code 작업 전에 기준안을 고정한다.

## 고정 원칙
- 첫 화면에서 **새 보고서 시작**이 바로 보여야 한다
- 입력은 최소화한다
- 사진 입력 후 결과를 빠르게 상상할 수 있어야 한다
- v1은 **보고서 생성**이 핵심이고, 부가 기능은 뒤로 미룬다

---

## Screen 1 — Home / Recent Reports

### 목적
- 사용자가 앱을 열자마자 새 보고서를 만들게 한다
- 최근 보고서로 다시 들어갈 수 있게 한다

### 핵심 요소
- 상단 타이틀: `보고서`
- Primary CTA: `새 보고서 만들기`
- 최근 보고서 리스트
- 빈 상태 메시지
- 마지막 작업 이어하기

### 추천 레이아웃
```text
┌─────────────────────────────┐
│ 보고서                      │
│                             │
│ [ 새 보고서 만들기 ]        │
│                             │
│ 최근 보고서                  │
│ ┌─────────────────────────┐ │
│ │ 2026-04-15 점검 보고서   │ │
│ │ 사진 6장 · 조치 필요 2   │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ 2026-04-14 현장 리포트   │ │
│ │ 사진 4장 · 완료          │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

### 상태
- 첫 실행 empty state
- 최근 보고서 있음
- 로딩 중

### 빈 상태 문구 예시
- `아직 보고서가 없습니다`
- `첫 보고서를 바로 만들어보세요`

---

## Screen 2 — New Report

### 목적
- 최소 입력으로 새 보고서를 시작한다

### 핵심 요소
- 프로젝트명 / 작업명 입력
- 날짜 자동 입력 또는 선택
- 위치 선택 또는 수동 입력
- 사진 추가 진입 버튼
- 시작 CTA

### 추천 레이아웃
```text
┌─────────────────────────────┐
│ 새 보고서 만들기            │
│                             │
│ 프로젝트명                  │
│ [____________________]      │
│                             │
│ 날짜                        │
│ [ 2026-04-15 ▼ ]            │
│                             │
│ 위치 / 작업명               │
│ [____________________]      │
│                             │
│ [ 사진 추가 ]               │
│                             │
│ [ 시작하기 ]                │
└─────────────────────────────┘
```

### 원칙
- 입력 항목은 3개 정도로 제한
- 템플릿 선택은 v1에서 숨기거나 아주 작게 둔다
- 사용자는 이 화면에서 오래 머물지 않아야 한다

### 상태
- 필수값 누락
- 입력값 있음
- 카메라 권한 거부

### CTA 문구 예시
- `시작하기`
- `사진 추가하고 계속`

## Screen 3 — Photo Input + Memo

### 목적
- 현장 사진을 빠르게 쌓고 각 사진에 짧은 메모를 붙인다

### 핵심 요소
- 카메라 촬영
- 갤러리 업로드
- 사진 썸네일 리스트
- 사진별 1줄 메모
- 사진 재정렬
- 다음 단계 진입

### 추천 레이아웃
```text
┌─────────────────────────────┐
│ 사진 추가                   │
│                             │
│ [ 카메라로 촬영 ]           │
│ [ 갤러리에서 선택 ]         │
│                             │
│ 사진 1                      │
│ ┌──────────┐                │
│ │ thumbnail │                │
│ └──────────┘                │
│ 메모                        │
│ [ 누수 흔적 확인 ]          │
│                             │
│ 사진 2                      │
│ ┌──────────┐                │
│ │ thumbnail │                │
│ └──────────┘                │
│ 메모                        │
│ [ 벽면 손상 ]               │
│                             │
│ [ 보고서 미리보기 ]         │
└─────────────────────────────┘
```

### 상태
- 사진 없음
- 사진 1장
- 사진 여러 장
- 업로드 실패
- 권한 거부

### 원칙
- 사진마다 메모는 짧게 1줄
- 재정렬은 가능하지만 복잡한 편집은 하지 않는다
- 사진 추가와 메모 입력이 가장 빨라야 한다

---

## 3개 화면의 연결 흐름
1. 홈에서 `새 보고서 만들기`
2. 새 보고서에서 프로젝트/날짜/작업명 입력
3. 사진 추가 화면에서 촬영/업로드 + 메모 입력
4. 미리보기로 넘어가기

---

## v1에서 아직 빼도 되는 것
- 템플릿 마켓
- AI 자동 판독 고도화
- 팀 권한
- 코멘트 / 협업
- 통계 / 분석
- 복잡한 리포트 편집기
- 다중 프로젝트 워크스페이스

---

## UX 판단 기준
이 3개 화면만 보고도 사용자가 아래를 즉시 알아야 한다.
- 무엇을 만드는 앱인지
- 사진을 어디서 넣는지
- 언제 결과가 나오는지
- PDF로 내보낼 수 있는지
