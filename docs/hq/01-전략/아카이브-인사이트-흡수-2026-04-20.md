# 아카이브 인사이트 흡수 - 2026-04-20

## 1. 핵심 신호 요약
- 오늘 corpus의 중심 신호는 `콘텐츠/AI`가 아니라 **유통-퍼널-운영체계**다.
- `shortsyoutuber`, `vibemoney`, `kongkey__`, `side.money_story`는 공통적으로 `콘텐츠 -> 신뢰 -> 전환` 구조를 반복한다.
- `ai.trend.ray`, `ai_margin_`, `brxce.ai`는 AI를 프롬프트 도구가 아니라 **작업 분해·승인·로그·동기화가 있는 운영 OS**로 다룬다.
- `worp_cy`, `dual__income`, `appnomad_lab`, `programmingzombie`는 작은 수익도 **반복 가능한 루틴과 저비용 자산화**로 만든다.

## 2. 오늘 새로 보인 패턴
- 숏폼/카페/Threads 운영자는 대체로 `교육자`보다 **퍼널 설계자**에 가깝다.
- 커뮤니티형 채널도 실제로는 활성 토론보다 **운영자 아카이브 + 리드 수집** 구조가 강하다.
- AI 빌더 계열은 모델 비교보다 **일을 쪼개고 다시 붙이는 운영 설계**를 더 자주 말한다.
- 성공 사례는 대형 제품보다 `첫 외주`, `첫 결제`, `작은 반복 수익`, `저비용 자동화`에 더 가까웠다.

## 3. 전일 대비 변화
- 큰 방향 전환은 없다. 기존의 `반복 비용 / 지불 주체 / 소수 인력` 기준이 유지된다.
- 다만 오늘은 그 기준 위에 **유통 경로의 선명도**와 **운영 체계의 자동화 가능성**이 더 강하게 보였다.
- 즉, "무엇을 만들까"보다 "어떻게 배포하고, 어떻게 반복 운영할까"가 더 중요한 쪽으로 기울었다.

## 4. 사업 반영 포인트
- 새 사업 아이디어는 기능 목록보다 먼저 **유통 경로**를 적어야 한다.
- 콘텐츠/교육형 사업은 설명력보다 **검증된 사례, 반복 가능한 CTA, 전환 동선**이 중요하다.
- 1인 운영은 대형 SaaS보다 **작은 외주, 단일 기능, 저비용 자동화, 반복 자산**이 더 현실적이다.
- TemperStone 관점에서는 "좋은 아이디어"보다 **지속 가능한 배포 구조**를 먼저 합격 기준으로 둬야 한다.

## 5. Claude Code / 하네스 인사이트
- AI를 쓸 때는 프롬프트보다 **작업 단위 절단**이 먼저다: 1 task → 1 output → 1 review.
- 승인 게이트, 로그, 동기화, source of truth를 문서/워크플로우 기본값으로 둬야 한다.
- 반복 작업은 사람 기억이 아니라 **문서화된 운영 루프**에 붙여야 한다.
- 하네스 문서는 "무엇을 시키는가"보다 **누가 승인하고 어디에 남기는가**를 더 명시해야 한다.

## 6. TemperStone HQ 문서 개선 포인트
- `01-전략`: 아이디어 평가 기준에 `유통 경로 / 전환 동선 / 반복 운영 가능성`을 명시.
- `02-제품`: 기획 카드에 `획득 채널`, `첫 전환 지점`, `운영 난이도`, `반복 수익 구조` 필드 추가.
- `05-운영`: 성과 기록과 운영 기록을 분리하고, 배포 후 전환/회수 데이터를 따로 적도록 수정.
- `07-회고`: 회고 템플릿에 `무엇이 잘 팔렸는가`보다 `무엇이 반복되었는가`를 넣기.

## 7. Hermes 인프라 개선 포인트
- archive-to-HQ sync는 **신선도 체크**를 기본으로 두고, 최신 raw와 최신 insight의 시차를 기록해야 한다.
- `thread-collector` 설정이 없어도 archive-only 흡수는 멈추지 않도록, source corpus 우선 탐색을 더 강하게 고정할 필요가 있다.
- daily report는 요약만 남기지 말고, **후속 의사결정용 메타데이터**(날짜, source root, freshness)를 같이 남겨야 한다.
- 반복되는 패턴은 나중에 비교할 수 있도록, 짧은 구조화 요약을 별도 인덱스로 쌓는 편이 좋다.
