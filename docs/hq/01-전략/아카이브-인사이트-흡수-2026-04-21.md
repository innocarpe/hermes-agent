# 아카이브 인사이트 흡수 - 2026-04-21

## 1. 핵심 신호 요약
- 오늘 corpus의 중심 신호는 여전히 **유통-퍼널-운영체계**다.
- `shortsyoutuber`, `vibemoney`는 커뮤니티보다 **운영자 아카이브 + 리드 수집 퍼널**에 가깝고, `ai.trend.ray`, `ai_margin_`, `brxce.ai`는 AI를 도구가 아니라 **작업 분해·승인·로그·동기화가 있는 운영 OS**로 다룬다.
- `dual__income`, `appnomad_lab`, `programmingzombie` 계열은 대형 제품보다 **첫 외주, 첫 결제, 작은 반복 수익, 저비용 자산화** 쪽에 더 가깝다.
- 오늘은 새 대형 신호보다, 기존 판단 기준이 계속 유효하다는 점이 더 강하게 확인됐다.

## 2. 오늘 새로 보인 패턴
- Threads/NaverCafe 모두에서 공통적으로 보이는 건 **콘텐츠 자체보다 전환 동선**을 먼저 짜는 방식이다.
- AI 빌더 계열은 모델 비교보다 **업무 흐름 재설계**를 더 많이 말한다. 즉 “무슨 AI를 쓰나”보다 “어떻게 쪼개고, 어디에 남기고, 누가 승인하나”가 핵심이다.
- 수익화 계열은 거대한 SaaS보다 **작은 납품 / 작은 자동화 / 작은 외주**에서 시작하는 패턴이 우세하다.
- 커뮤니티형 채널도 실제로는 커뮤니티 운영보다 **운영자 브랜드와 리드 캡처**가 중심이다.

## 3. 전일 대비 변화
- 큰 방향 전환은 없다. 전일 보고와 비교해도 `distribution first`, `repeatable loop`, `small paid outcome` 기준이 그대로 유지된다.
- 새 raw corpus가 추가된 흔적은 보이지 않았고, 최신 raw와 최신 insight의 시차도 크지 않아 **백로그 신호는 약함**으로 본다.
- 따라서 오늘은 “새로운 큰 결론”보다 **기존 결론의 재확인**이 핵심이다.

## 4. 사업 반영 포인트
- 새 사업/기획은 기능 목록 전에 **유통 경로와 첫 전환 지점**을 먼저 써야 한다.
- 판단 기준은 `누가 사는가`보다 `어떻게 들어오고, 어디서 결제하고, 무엇이 반복되는가`다.
- 1인 운영 기준에서는 대형 제품보다 **저비용 납품, 단일 기능, 작은 자동화, 반복 자산**이 먼저 합격이다.
- TemperStone 관점에서는 아이디어보다 **지속 가능한 배포 구조**가 우선 게이트다.

## 5. Claude Code / 하네스 인사이트
- AI 작업은 프롬프트보다 **작업 단위 절단**이 먼저다: `1 task → 1 output → 1 review`.
- 승인 게이트, 로그, source of truth, 동기화 지점을 기본값으로 두는 편이 맞다.
- 반복 작업은 사람 기억이 아니라 **문서화된 운영 루프**에 붙여야 한다.
- 하네스 문서는 “무엇을 시키는가”보다 **누가 승인하고 어디에 남기는가**를 더 명시해야 한다.

## 6. TemperStone HQ 문서 개선 포인트
- `01-전략`: 아이디어 평가 기준에 `유통 경로 / 첫 전환 지점 / 반복 운영 가능성`을 고정 필드로 둔다.
- `02-제품`: 기획 카드에 `획득 채널`, `첫 결제 지점`, `운영 난이도`, `반복 수익 구조`를 넣는다.
- `05-운영`: 성과 기록과 운영 기록을 분리하고, 배포 후 전환/회수 데이터를 별도 항목으로 적는다.
- `07-회고`: “무엇이 잘 팔렸는가”와 함께 “무엇이 반복되었는가 / 어디서 막혔는가”를 남긴다.
- HQ 문서는 결과 요약보다 **의사결정에 재사용 가능한 체크리스트** 형태로 더 수렴해야 한다.

## 7. Hermes 인프라 개선 포인트
- archive-to-HQ sync는 **raw freshness / insight freshness / gap**을 자동 기록해야 한다.
- source corpus root 탐색과 HQ destination 저장을 더 강하게 분리해, 설정 부재가 곧 무신호로 오해되지 않게 해야 한다.
- weak-signal day에도 watchlist를 남기고, 무신호 판정은 **raw corpus 확인 후**에만 내리도록 고정해야 한다.
- 반복되는 패턴은 짧은 구조화 메모로 축적해, 다음 날 비교가 쉬워야 한다.

## 8. 오늘의 우선순위
1. 새 기획은 무조건 `distribution first`로 평가한다.
2. Claude Code / 하네스 작업은 `task slicing + 승인 + 로그` 규칙을 유지한다.
3. HQ 문서에는 `첫 전환 지점`과 `반복 가능성` 필드를 빠뜨리지 않는다.
