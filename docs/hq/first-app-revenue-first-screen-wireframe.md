# First App Revenue Playbook — First Screen Wireframe

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
첫 번째 화면에서 사용자가 무엇을 해야 하는지 즉시 이해하게 만든다.

## 원칙
- 첫 화면에서 정보는 적게
- 행동은 하나만 강하게
- 사용자는 "새 점검 보고서 시작"만 보면 된다
- 첫 화면은 설명보다 **시작 버튼**이 중심

## 추천 첫 화면 구조

```text
┌──────────────────────────────────┐
│  사진 → 보고서                   │
│  빠르게 보고서를 만드세요        │
│                                  │
│  [ + 새 점검 보고서 시작 ]            │
│                                  │
│  최근 보고서                     │
│  - 2026-04-15 현장 점검          │
│  - 2026-04-14 피해 기록          │
│                                  │
│  템플릿                          │
│  • 간단 보고서                   │
│  • 점검 보고서                   │
└──────────────────────────────────┘
```

## 첫 화면에서 보여줄 것
- 앱의 핵심 가치 1문장
- 새 점검 보고서 시작 버튼 1개
- 최근 보고서 2~3개
- 템플릿 진입점 1개

## 첫 화면에서 숨길 것
- OCR 고도화
- AI 자동 요약 옵션
- 복잡한 설정
- 계정/동기화
- 팀 협업

## 왜 이렇게 두는가
- 사용자는 처음부터 많은 기능을 원하지 않는다
- 첫 행동을 단순화해야 보고서 생성으로 들어간다
- 최근 보고서를 보여주면 앱의 실제 용도를 바로 이해한다

## 다음 화면으로 이어지는 흐름
1. 새 점검 보고서 시작
2. 사진 추가
3. 사진별 메모 입력
4. 템플릿 선택
5. 미리보기
6. PDF 내보내기 / 공유

## 판단 기준
첫 화면을 본 사용자가 아래 질문에 즉시 답할 수 있어야 한다.
- 이 앱으로 뭘 하지?
- 지금 뭘 눌러야 하지?
- 결과는 어디서 나오지?
