# First App Strategy Principles

## 목적
첫 앱 관련 문서들을 하나의 판단 기준으로 묶어서, 앞으로 새 후보를 볼 때 같은 기준으로 빠르게 판정할 수 있게 한다.

## 핵심 원칙
- **반복 비용이 큰 문제**를 먼저 본다.
- **누가 돈을 내는지**가 분명해야 한다.
- **소수 인력으로 운영 가능한 구조**여야 한다.
- 범용 앱보다 **좁은 워크플로 문제**를 먼저 본다.
- 광고 단독보다 **Pro unlock / 크레딧 / 구독** 가능성을 함께 본다.
- 흐름은 항상 **입력 → 처리 → 결과 → 공유**처럼 짧아야 한다.

## TemperStone HQ 적용 방식

### 전략 판단
- 시장이 크다보다 **반복 사용되는가**를 먼저 본다.
- 니치가 작아 보여도 **지불 주체가 명확하면** 우선 검토한다.
- 제품이 아니라 **문제 정의의 질**을 먼저 본다.

### 제품 판단
- 첫 앱은 플랫폼이 아니라 **한 가지 반복 작업**을 해결해야 한다.
- MVP는 1개월 안에 만들 수 있을 정도로 좁게 자른다.
- 기능 수보다 **반복 비용 절감**과 **결과물의 즉시 가치**를 먼저 본다.

### 수익화 판단
- 광고는 보조 수단으로 둔다.
- 기본 수익화 후보는 **Pro unlock / 크레딧 / 구독**이다.
- 무료 버전은 핵심 가치를 보여주되, 유료 버전은 반복 가치와 운영 편의를 강화해야 한다.

### 운영 판단
- 소수 인력으로 유지 가능한지 항상 확인한다.
- 고비용 API나 복잡한 협업 구조가 들어오면 MVP 범위를 다시 자른다.
- `03-콘텐츠`, `04-채널`, `05-운영` 문서와 충돌하지 않도록 역할을 분리한다.

## 실행 체크리스트

- [ ] 지불 주체가 누군지 적는다.
- [ ] 소수 인력 운영 가능성을 적는다.
- [ ] 1개월 MVP 범위로 자를 수 있는지 확인한다.
- [ ] 광고 단독이 아니라 Pro unlock / 크레딧 / 구독 후보를 검토한다.
- [ ] 흐름이 입력 → 처리 → 결과 → 공유로 짧은지 확인한다.
