# First App Revenue Playbook — Template Selection Wireframe

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
사용자가 보고서의 형식을 너무 고민하지 않도록 템플릿 선택을 단순하게 만든다.

## 원칙
- 템플릿은 2~3개만 보여준다
- 차이는 명확해야 한다
- 미리보기 썸네일로 바로 이해돼야 한다
- 사용자는 "어느 형식이 맞지?"를 10초 안에 결정해야 한다

## 추천 화면 구조

```text
┌──────────────────────────────────┐
│  템플릿 선택                     │
│                                  │
│  [ 간단 보고서 ]                 │
│  - 사진 + 메모 중심              │
│                                  │
│  [ 점검 보고서 ]                 │
│  - 상태 요약 포함                │
│                                  │
│  [ 피해 기록 ]                   │
│  - 증빙 중심                     │
│                                  │
│  [ 미리보기 ]     [ 계속 ]      │
└──────────────────────────────────┘
```

## 화면에서 보여줄 것
- 템플릿 이름
- 한 줄 설명
- 선택 상태
- 미리보기 버튼
- 계속 버튼

## 화면에서 숨길 것
- 템플릿 편집
- 복잡한 레이아웃 설정
- 공유 옵션
- 고급 스타일 옵션

## 중요한 UX 포인트
- 기본값이 하나는 선택돼 있어야 한다
- 템플릿 이름은 업무 맥락으로 이해돼야 한다
- 선택하지 않으면 다음으로 못 가게 하는 편이 안전하다
- 템플릿은 나중에 Pro 기능으로 확장하기 쉽다

## 다음 화면으로 이어지는 흐름
1. 템플릿 선택
2. 미리보기에서 결과 확인
3. PDF 내보내기 / 공유

## 판단 기준
이 화면을 본 사용자가 아래를 즉시 이해해야 한다.
- 템플릿이 왜 필요한지
- 어떤 템플릿을 골라야 하는지
- 선택 후 어디로 가는지

## 다음 액션
- 이 흐름을 시작 화면부터 미리보기까지 한 줄로 연결한다
- 나중에 상태별 템플릿 차등도 고려한다
