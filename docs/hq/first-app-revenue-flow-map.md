# First App Revenue Playbook — End-to-End Flow Map

## 목적
앱의 핵심 흐름을 한 장으로 묶어서, 화면 간 연결이 끊기지 않도록 한다.

## 핵심 플로우

```text
첫 화면
  ↓
새 점검 보고서 시작
  ↓
사진 추가
  ↓
사진별 메모 입력
  ↓
템플릿 선택
  ↓
미리보기 / PDF
  ↓
공유 / 완료
```

## 흐름 원칙
- 한 단계당 한 가지 행동만 강하게 보여준다
- 돌아가기 / 수정은 가능하지만 주 흐름을 흐리게 하지 않는다
- 사용자는 언제든지 지금 위치를 알아야 한다
- 흐름은 **반복 비용을 줄이는 방향**으로만 늘린다
- 결과를 내는 사용자와 비용을 내는 사용자가 분리되면 그 관계를 먼저 문서화한다
- 자세한 판정 기준은 `docs/hq/first-app-strategy-principles.md`를 따른다.

## 단계별 역할

### 1) 첫 화면
- 앱의 존재 이유를 보여준다
- 새 점검 보고서 시작으로 진입시킨다

### 2) 사진 추가
- 입력 재료를 모은다
- 사용자가 보고서 재료를 확보했다는 느낌을 준다

### 3) 사진별 메모 입력
- 사진의 의미를 구조화한다
- 결과가 단순 갤러리가 아니라 문서라는 느낌을 준다

### 4) 템플릿 선택
- 출력 형식을 정리한다
- 사용자의 고민을 줄인다

### 5) 미리보기 / PDF
- 결과를 최종 문서처럼 보여준다
- 내보내기 결정을 돕는다

### 6) 공유 / 완료
- 실제 사용 가치가 완성됐는지 확인한다
- 다음 보고서로 돌아갈 수 있게 한다

## 어디서 막히면 안 되는가
- 첫 화면에서 시작점이 안 보이면 안 된다
- 사진 추가에서 업로드가 어렵면 안 된다
- 메모 입력이 길어지면 안 된다
- 템플릿 선택이 복잡하면 안 된다
- PDF 생성이 느리면 안 된다

## 판단 기준
이 플로우를 보는 사용자가 아래를 즉시 이해해야 한다.
- 무엇부터 시작하는지
- 각 단계가 왜 필요한지
- 어디서 최종 결과가 나오는지
