# First App Revenue — Photo-to-Report Screen Map

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
`사진 → 보고서 생성` 앱의 MVP UX를 실제 디자인 작업에 들어가기 전에 최대한 좁혀서 정의한다.

## 핵심 사용자 흐름
1. 홈에서 새 보고서 시작
2. 사진 추가
3. 사진별 짧은 메모 입력
4. 보고서 미리보기 확인
5. PDF 내보내기 / 공유

## 화면 1: 홈 / 최근 보고서
### 목표
- 사용자가 바로 새 보고서를 시작할 수 있게 한다
- 최근 보고서 재진입 경로를 제공한다

### 포함 요소
- `새 보고서 만들기` CTA
- 최근 보고서 리스트
- 마지막 작업 이어하기

### 상태
- 첫 실행 empty state
- 최근 보고서 존재 state
- 로딩 state

## 화면 2: 새 보고서 만들기
### 목표
- 최소 입력으로 보고서 작업을 시작한다

### 포함 요소
- 프로젝트명
- 날짜
- 위치 / 작업명 선택 또는 입력
- 사진 추가
- 시작 CTA

### 원칙
- 폼은 짧아야 한다
- 복잡한 템플릿 선택은 v1에서 최소화한다

## 화면 3: 사진 입력 + 메모
### 목표
- 현장 사진을 빠르게 쌓고 각 사진에 코멘트를 붙인다

### 포함 요소
- 카메라 촬영
- 갤러리 업로드
- 사진 썸네일 리스트
- 사진별 1줄 메모
- 사진 재정렬

### 상태
- 사진 없음
- 사진 1장
- 사진 여러 장
- 업로드 실패

## 화면 4: 보고서 미리보기
### 목표
- 결과물을 거의 최종본처럼 보여준다

### 포함 요소
- 제목
- 날짜
- 섹션별 사진
- 사진 설명
- 기본 로고 / 브랜드
- PDF 생성 전 미리보기

### 원칙
- 미리보기가 결과물이다
- 편집은 가볍게만 허용한다

## 화면 5: PDF 내보내기 / 공유
### 목표
- 결과물을 즉시 전달한다

### 포함 요소
- PDF 다운로드
- 공유 버튼
- 메신저 / 이메일 / 드라이브 공유
- 저장 완료 확인

### 상태
- PDF 생성 중
- 생성 실패
- 공유 성공

## MVP에서 꼭 필요한 상태
- empty
- loading
- error
- photo permission denied
- export failure
- offline / weak network

## MVP에서 아직 빼도 되는 것
- 템플릿 마켓
- 팀 권한
- 댓글 / 협업
- 분석 대시보드
- OCR 고급 판독
- 다중 문서 비교
- 엔터프라이즈 설정

## UX 우선순위
1. 사진 추가가 가장 빠른가
2. 메모 입력이 가장 짧은가
3. 미리보기가 바로 쓸 만한가
4. PDF 내보내기가 명확한가
5. 다시 돌아와서 또 만들고 싶은가

## 디자인에 넘기기 전 확인할 질문
- 첫 화면에서 새 보고서 CTA가 충분히 선명한가?
- 사진 입력 후 바로 결과를 볼 수 있는가?
- 미리보기가 실제 업무 문서처럼 느껴지는가?
- 공유보다 내보내기가 1차 행동으로 보이는가?
- Android 네비게이션 관습에 맞는가?
