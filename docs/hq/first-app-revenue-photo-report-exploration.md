# First App Revenue — Photo-to-Report Exploration

## 목적
현재 탐색 중인 앱 아이디어 중 **가장 우선순위가 높은 안**인 `사진 → 보고서 생성` 앱을 TemperStone HQ 기준으로 정리한다.

이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 따라 읽는 **전략/제안 문서**다.

이 문서는 다음 단계인 UX 설계 / 추가 리서치 / 구현 준비를 위한 **탐색용 SSOT 초안**이다.

## 현재 결론
- **플랫폼 우선순위:** Android-first
- **앱 방향:** 현장 사진과 짧은 메모를 빠르게 정리해서 **깔끔한 PDF 보고서**로 내보내는 앱
- **핵심 wedge:** `카메라 먼저, 보고서 자동 생성`
- **검증 상태:** 아직 탐색 단계

## 왜 이 방향인가
- 실제 사용자군이 이미 존재한다
- 경쟁앱이 이미 존재한다
- 글로벌-first로도 자연스럽다
- 한 달 안에 MVP로 자를 수 있다
- 범용 스캐너보다 차별화 포인트가 더 명확하다

## 주요 사용자
- 현장 작업자
- 점검/검사 담당자
- 소규모 운영팀
- 사진 기반 보고가 필요한 프리랜서/소규모 사업자
- 건설/시설/유지보수/보험/점검 관련 사용자

## 대표 사용 시나리오
1. 현장에서 사진을 찍는다
2. 짧은 메모를 붙인다
3. 보고서 제목/프로젝트명을 넣는다
4. 앱이 사진 순서와 섹션을 정리한다
5. PDF로 내보내고 공유한다

## 1차 MVP 범위

### 포함할 기능
- 사진 촬영 / 업로드
- 프로젝트명 / 작업명 / 날짜 입력
- 사진별 짧은 메모
- 자동 보고서 미리보기
- PDF 내보내기
- 링크 / 메신저 / 이메일 공유
- 기본 브랜딩 로고 / 제목

### 제외할 기능
- 복잡한 폼 빌더
- 팀 권한 / 승인 워크플로
- 실시간 협업
- 고급 AI 판독 / 상세 OCR 파이프라인
- 대시보드 / 분석
- 다중 템플릿 스튜디오
- 엔터프라이즈형 admin 콘솔

## 현재 UX 원칙
- 첫 화면은 **보고서 생성 행동**이 보이게 한다
- 사용자가 앱을 열었을 때 "무엇을 해야 하는지" 바로 이해해야 한다
- 보고서 미리보기가 결과물의 거의 최종 형태여야 한다
- 편집은 깊게 들어가지 말고, 최소한의 수정만 허용한다
- 공유보다 **내보내기**를 1차 행동으로 둔다

## 권장 첫 화면
### 화면명: 새 보고서 만들기
필수 입력:
- 프로젝트명
- 날짜
- 사진 추가
- 짧은 메모

주요 CTA:
- `PDF 생성`

## 권장 정보구조
1. 홈 / 최근 보고서
2. 새 보고서 만들기
3. 사진 입력 및 메모
4. 보고서 미리보기
5. PDF 내보내기 / 공유

## 현재 벤치마크 방향
이 아이디어는 아래 유형의 경쟁앱과 비교해야 한다.
- CompanyCam
- SafetyCulture (iAuditor)
- Fulcrum
- GoCanvas
- Dashpivot / Snappii 계열

### 벤치마크에서 확인할 것
- 첫 3화면이 얼마나 빠른가
- 템플릿 선택이 필수인지
- 폼 빌더가 초기 진입장벽인지
- PDF 출력이 얼마나 전면에 있는지
- 공유 흐름이 얼마나 쉬운지
- 가격이 seat-based인지, usage-based인지, freemium인지

## 수익화 초안
- Free: 제한된 보고서 생성 횟수
- Pro: 무제한 PDF / 브랜드 로고 / 고해상도 export / 추가 템플릿

## Android-first로 보는 이유
- 카메라/파일/공유 흐름과 잘 맞음
- 현장형 사용자에게 자연스러움
- 실험과 배포가 빠름
- 저비용으로 글로벌 검증하기 좋음

## 다음에 해야 할 일
1. 이 앱의 **첫 3개 화면**을 확정한다
2. 경쟁앱의 **온보딩 / 가격 / 첫 사용 경험**을 다시 본다
3. MVP에서 필요한 토큰 / 컴포넌트를 정리한다
4. Stitch / Pencil MCP / Figma 중 무엇으로 초안을 만들지 정한다
5. Claude Code로 들어가기 전에 scope를 더 줄인다

## 열린 질문
- 대상 사용자를 더 좁히면 어디가 가장 좋은가?
- PDF 보고서의 기본 템플릿은 1개로 시작할지 2~3개로 시작할지?
- OCR은 v1에서 넣을지, v2로 미룰지?
- 현장 사진이 많은 사용자 vs 문서 사진이 많은 사용자 중 누구를 먼저 잡을지?
- Android만 먼저 갈지, iOS는 나중에 확장할지?

## 한줄 결론
**현장 사진을 빠르게 정리해서 바로 보고서로 내보내는 Android-first 앱이 현재 탐색 중인 가장 현실적인 1차 후보다.**
