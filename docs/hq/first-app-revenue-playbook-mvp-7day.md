# First App Revenue Playbook — MVP 7일 플랜

## 목적
현재 시장조사 결과를 바탕으로, 가장 유력한 방향인 **사진 → 보고서 / 문서화 앱**을 7일 안에 검증 가능한 MVP로 쪼갠다.

## 전제
- 글로벌-first
- 1개월 MVP 가능 범위
- 범용 앱이 아니라 **반복 사용되는 니치 문제**를 푼다
- 수익화는 광고 단독이 아니라 **Pro unlock / 크레딧 / 구독 후보**까지 열어둔다
- 자세한 판정 기준은 `docs/hq/first-app-strategy-principles.md`를 따른다.

## MVP 한줄 정의
> 사용자가 사진을 찍고, 짧은 메모를 붙이고, 템플릿을 선택해서, 바로 공유 가능한 PDF 보고서를 만드는 앱

## 이번 MVP에서 반드시 확인할 것
1. 사용자가 이 흐름을 이해하는가
2. 사진 → 메모 → 템플릿 → PDF의 핵심 흐름이 자연스러운가
3. 사용자가 결과물을 실제로 공유할 이유가 있는가
4. 무료 버전과 유료 버전의 경계가 설득력 있는가
5. 이 앱이 반복 사용될 가능성이 있는가

---

## Day 1 — 문제 정의와 범위 고정

### 목표
앱의 타깃과 사용 시나리오를 하나로 좁힌다.

### 해야 할 일
- 타깃을 1개만 고른다.
  - 홈 인스펙션 / 부동산 점검
  - 시설 유지보수
  - 현장 작업 기록
  - 보험 / 피해 기록
  - 소규모 팀 점검 리포트
- 핵심 작업 흐름을 1개로 고정한다.
- MVP에서 제외할 기능을 적는다.

### 제외할 것
- 팀 협업
- 계정/권한 시스템
- 동기화
- OCR 고도화
- AI 자동 요약 고도화
- 복잡한 폼 빌더

### 산출물
- 타깃 고객 1개
- 핵심 시나리오 1개
- 제외 기능 리스트

---

## Day 2 — 화면 흐름 설계

### 목표
최소 화면 구조를 정리한다.

### 화면 순서
1. 홈 / 새 보고서 시작
2. 사진 추가
3. 사진별 메모 입력
4. 템플릿 선택
5. 미리보기
6. PDF 내보내기 / 공유

### 확인할 점
- 첫 화면에서 무엇을 바로 눌러야 하는가
- 사진을 여러 장 넣는 흐름이 자연스러운가
- 공유 버튼이 결과 페이지에서 명확한가

### 산출물
- 6개 화면의 와이어프레임
- 각 화면에서 한 번에 보여줄 정보

---

## Day 3 — 핵심 입력 / 결과 구조 구현

### 목표
사진과 메모를 모아 하나의 보고서 초안으로 만드는 핵심 구조를 만든다.

### 해야 할 일
- 사진 추가 기능
- 사진별 메모 입력
- 상태 태그 2~3개
  - 예: 정상 / 주의 / 조치 필요
- 템플릿 2종
  - 예: 간단 보고서 / 점검 보고서

### 핵심 원칙
- 기능을 넓히지 않는다
- 보고서 결과가 “정돈되어 보이는가”를 먼저 본다
- 텍스트 자동 생성보다 **구조화된 출력**이 먼저다

### 산출물
- 사진 + 메모 + 템플릿이 한 보고서로 묶이는지 확인

---

## Day 4 — PDF 생성과 공유

### 목표
사용자가 결과를 실제로 내보낼 수 있게 한다.

### 해야 할 일
- PDF 생성
- 파일 저장
- 링크 또는 공유 시트 연동
- 공유 전 미리보기

### 확인할 점
- PDF가 실제 업무에 쓸 만한가
- 제목 / 날짜 / 사진 / 메모 / 상태가 읽히는가
- 출력 품질이 납득 가능한가

### 산출물
- 공유 가능한 PDF 1개
- 내보내기 실패 케이스 점검

---

## Day 5 — 수익화 장치 설계

### 목표
무료 체험과 유료 가치의 경계를 정한다.

### 추천 방식
- Free
  - 제한된 보고서 수
  - 기본 템플릿만 제공
- Pro unlock
  - 템플릿 추가
  - 무제한 내보내기
  - 고급 PDF 포맷
- 크레딧형 과금 후보
  - AI 요약 / OCR / 자동 정리

### 확인할 점
- 사용자가 유료화 이유를 이해하는가
- 광고 없이도 유료 전환 이유가 생기는가
- 무료 버전만으로도 핵심 가치를 체험할 수 있는가

### 산출물
- 가격 실험안 2개
- Free / Pro 경계표

---

## Day 6 — 내부 테스트와 수정

### 목표
실제 사용 시 막히는 지점을 찾는다.

### 테스트 질문
- 첫 보고서 생성까지 몇 초 걸리는가
- 사진 추가가 귀찮지 않은가
- 메모 입력이 번거롭지 않은가
- 결과물이 바로 공유할 만한가
- 유사 앱과 비교했을 때 왜 더 나은가

### 수정 우선순위
1. 첫 사용 장벽
2. 보고서 품질
3. 공유 흐름
4. 유료 경계

### 산출물
- 막힘 포인트 5개 이하로 축소
- 수정 리스트

---

## Day 7 — 출시 판단

### 목표
MVP를 계속 밀지, 방향을 바꿀지 결정한다.

### 출시 판단 기준
- 첫 흐름이 30초 안에 이해되는가
- 보고서 결과가 쓸 만한가
- 반복 사용 시나리오가 보이는가
- 수익화 장치가 설득력 있는가
- 더 좁은 니치로 자를 필요가 있는가

### 결과 판정
- **GO**: 바로 다음 2주 개발 플랜으로 이동
- **HOLD**: 같은 방향으로 기능 보강
- **NO-GO**: 타깃을 더 좁히거나 다른 기회 공간으로 이동

---

## 성공 기준
- 사용자가 첫 보고서를 만들어 본다
- 결과물을 공유해 본다
- 반복 사용 가능성이 확인된다
- 유료화 이유를 설명할 수 있다

## 실패 신호
- 흐름 설명이 길어야 이해된다
- 결과물이 평범해서 굳이 쓸 이유가 약하다
- PDF/보고서 생성이 너무 무겁다
- 타깃이 너무 넓어서 기능이 계속 늘어난다

## HQ 메모
이 MVP는 "첫 앱 매출"을 위한 게 아니라, **시장 신호가 강한 니치 문제를 실제 제품으로 바꿔보는 첫 실험**이다.
