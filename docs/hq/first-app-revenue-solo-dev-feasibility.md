# First App Revenue Playbook — Solo Dev Feasibility

## 왜 이 문서가 중요한가
우성님은 1인 개발자로서 **혼자 구현 가능한가**와 **얼마나 오래 걸리는가**를 최우선으로 본다. 그래서 시장성만이 아니라, 실제로 1인이 1개월 안에 만들 수 있는가를 별도로 판정한다.

이 문서는 `docs/hq/first-app-strategy-principles.md`의 **운영/난이도 판단**을 풀어쓴 보조 문서다.

## 판정 기준
다음 항목이 많을수록 1인 개발 난이도가 올라간다.
- 로그인/권한/협업
- 실시간 동기화
- 복잡한 백엔드
- OCR / AI 처리 비용
- 여러 사용자 역할
- 폼 빌더 / 규칙 엔진
- 엔터프라이즈 통합
- 오프라인 우선 + 충돌 해결

반대로 아래 요소가 많을수록 1인 개발에 유리하다.
- 단일 사용자 흐름
- 로컬 저장 중심
- 템플릿 고정
- PDF 내보내기
- 단순한 상태값
- 적은 화면 수
- 서버 없이도 동작 가능한 핵심 흐름

---

## 후보별 1인 개발 적합성

### 1) 사진 → 보고서 / 문서화 앱
**판정:** 가능

**이유**
- 핵심 흐름이 짧다
- 화면 수를 5~6개로 묶을 수 있다
- 로컬 저장 + PDF export로도 MVP가 성립한다
- 계정/동기화를 빼면 구현 부담이 크게 줄어든다

**주의**
- OCR, AI 요약, 팀 협업을 붙이면 바로 무거워진다
- 템플릿을 너무 많이 만들면 유지보수가 늘어난다

**1인 개발 결론**
- **가능**
- 단, **local-first + template-based + export-first**로 제한해야 한다

---

### 2) Shift handover / daily operations logbook
**판정:** 조건부 가능

**이유**
- 핵심은 단순할 수 있다
- 그러나 실제 사용 맥락이 여러 사람/여러 교대/여러 site로 확장되기 쉽다
- 권한, 계정, 동기화, 공유가 빨리 필요해질 수 있다

**1인 개발 결론**
- 초미니 버전은 가능
- 하지만 제품이 자연스럽게 커질 가능성이 높아 1개월 MVP에선 관리가 어렵다

---

### 3) Receipt / invoice capture → expense export
**판정:** 조건부 가능

**이유**
- 수요는 강함
- 하지만 OCR 정확도, 분류, export, 회계 포맷 대응이 부담
- 외부 연동이 늘면 복잡도가 빠르게 증가한다

**1인 개발 결론**
- 매우 작은 버전은 가능
- 하지만 “쓸 만한” 수준을 만들려면 생각보다 오래 걸릴 수 있다

---

### 4) Fleet / equipment inspection notes
**판정:** 가능하나 타깃이 좁아야 함

**이유**
- 현장 점검 흐름은 단순하게 만들 수 있다
- 다만 도메인 지식과 타깃 분리가 중요하다
- 범용화하면 기능이 늘어나기 쉽다

**1인 개발 결론**
- MVP는 가능
- 하지만 첫 고객 세그먼트를 잘못 잡으면 메시지가 약해진다

---

### 5) Mobile document scanner → PDF/OCR
**판정:** 가능하지만 경쟁이 너무 강함

**이유**
- 기술적으로는 만들 수 있다
- 그러나 차별화가 어렵고, 기능 경쟁이 빨리 시작된다

**1인 개발 결론**
- 1인 개발 가능성과 별개로, 사업적으로는 덜 추천

---

## 최종 추천

### 1인 개발 + 1개월 MVP 기준 1순위
> **사진 → 보고서 / 문서화 앱**

### 왜 이게 맞는가
- 기능이 가장 잘 잘린다
- 화면이 적다
- 로컬 중심으로 시작할 수 있다
- PDF라는 명확한 출력이 있다
- 혼자서도 구현 범위를 통제하기 쉽다

### 1인 개발에서 반드시 지켜야 할 제한
- 로그인 없음
- 팀 협업 없음
- 실시간 동기화 없음
- OCR 없음 또는 후순위
- AI 자동 생성 없음 또는 후순위
- 템플릿 2~3개만
- PDF export만 먼저

---

## 솔직한 결론
이 앱은 **혼자 만들 수 있는 수준**입니다.
다만 조건이 있습니다:
- **범위를 극단적으로 좁혀야 하고**
- **서버/AI/동기화 욕심을 초반에 버려야 하며**
- **“현장 사진 → 메모 → 상태 → PDF”만 먼저 끝내야** 합니다.

즉, 이건 “혼자서 가능한 앱”이지, “혼자서도 기능을 계속 늘려도 되는 앱”은 아닙니다.

## 다음 액션
1. MVP를 local-first로 고정한다.
2. 로그인/동기화/AI를 이번 버전에서 제외한다.
3. 구현 티켓에 예상 공수를 붙여서 1개월 안에 끝나는지 다시 본다.
