# First App Revenue — Photo-to-Report Preview Screen

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
보고서가 실제로 쓸 만한지 사용자가 바로 확인하고, 바로 내보낼 수 있게 한다.

## 이 화면의 역할
- 보고서의 최종 형태를 보여준다
- 편집보다 확인과 내보내기를 우선한다
- 사용자가 "이 앱이 뭐 하는지" 즉시 이해하게 만든다

## 핵심 원칙
- 미리보기가 곧 결과물이다
- PDF 내보내기는 가장 눈에 잘 띄게 둔다
- 공유는 2차 행동으로 둔다
- 편집은 깊게 들어가지 않고, 필요한 항목만 되돌아가서 수정한다

## 추천 화면 구조
```text
┌─────────────────────────────┐
│ 보고서 미리보기             │
│                             │
│ 제목: 2026-04-15 점검 보고서│
│ 상태: 조치 필요 3 / 주의 2  │
│                             │
│ [ 사진 1 ]                  │
│ 메모: 누수 흔적 확인        │
│                             │
│ [ 사진 2 ]                  │
│ 메모: 벽면 손상             │
│                             │
│ [ 사진 3 ]                  │
│ 메모: 장비 위치 정상        │
│                             │
│ 템플릿: 간단 보고서         │
│                             │
│ [ PDF 내보내기 ]            │
│ [ 공유하기 ]                │
└─────────────────────────────┘
```

## 포함 요소
- 보고서 제목
- 날짜
- 상태 요약
- 사진 + 메모 리스트
- 템플릿 정보
- PDF 내보내기 버튼
- 공유 버튼

## 상태
- PDF 생성 중
- PDF 생성 실패
- 저장 권한 없음
- 사진 누락
- 네트워크 약함

## UX 포인트
1. 사용자가 결과물을 한눈에 이해해야 한다
2. 내보내기 버튼이 명확해야 한다
3. 공유는 빠르되, 내보내기보다 덜 강하게 보여도 된다
4. 미리보기를 보고 다시 수정할 수 있어야 한다

## v1에서 빼도 되는 것
- 상세 편집기
- 텍스트 정렬/서식 제어
- 섹션 추가/삭제 UI
- 다중 템플릿 마켓
- 협업 댓글
- 분석 대시보드

## 되돌아가기 흐름
- 제목 수정이 필요하면 이전 화면으로
- 사진 순서 수정이 필요하면 사진 입력 화면으로
- 템플릿 수정은 v1에서 최소화

## 판단 기준
이 화면만 봐도 아래를 즉시 알아야 한다.
- 최종 보고서가 어떻게 생기는지
- 지금 바로 내보낼 수 있는지
- 어디를 수정해야 하는지
