# First App Revenue Playbook — Preview / PDF Wireframe

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
최종 보고서가 실제로 쓸 만한지 확인하고, 바로 내보내게 만든다.

## 원칙
- 미리보기는 결과를 가장 먼저 보여준다
- 편집은 필요할 때만 가능해야 한다
- 내보내기 버튼은 화면에서 명확해야 한다
- 결과물이 “업무에서 바로 쓰는 문서”처럼 보여야 한다

## 추천 화면 구조

```text
┌──────────────────────────────────┐
│  보고서 미리보기                 │
│                                  │
│  제목: 2026-04-15 점검 보고서    │
│  상태: 조치 필요 3 / 주의 2      │
│                                  │
│  [ 사진 1 ]                      │
│  메모: 누수 흔적 확인            │
│                                  │
│  [ 사진 2 ]                      │
│  메모: 벽면 손상                 │
│                                  │
│  템플릿: 간단 보고서             │
│                                  │
│  [ PDF 내보내기 ]                │
│  [ 공유하기 ]                    │
└──────────────────────────────────┘
```

## 화면에서 보여줄 것
- 제목
- 날짜
- 상태 요약
- 사진 + 메모
- 템플릿 정보
- 내보내기 / 공유 버튼

## 화면에서 숨길 것
- 고급 설정
- 불필요한 필터
- 세부 레이아웃 조정
- 내부 시스템 정보

## 중요한 UX 포인트
- 미리보기가 곧 결과물이어야 한다
- PDF 내보내기는 1차 행동으로 보여야 한다
- 공유는 2차 행동으로 보여도 된다
- 편집은 “돌아가서 수정” 흐름으로 처리하면 된다

## 실패 상태
- PDF 생성 중
- PDF 생성 실패
- 저장 권한 없음
- 사진 누락

## 다음 화면으로 이어지는 흐름
1. 미리보기 확인
2. PDF 내보내기
3. 공유 시트 호출
4. 완료 화면 또는 최근 보고서로 복귀

## 판단 기준
이 화면을 본 사용자가 아래를 즉시 이해해야 한다.
- 결과물이 어떤 모습인지
- 바로 내보낼 수 있는지
- 무엇이 부족한지
