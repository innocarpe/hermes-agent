# First App Revenue Playbook — Photo Note Input Wireframe

> 참고: 이 문서는 `docs/hq/first-app-strategy-principles.md`와 `docs/hq/first-app-doc-map.md`를 기준으로 읽는 보조 문서다.

## 목적
사진마다 짧은 메모와 상태를 가장 적은 마찰로 붙이게 만든다.

## 원칙
- 메모는 길게 쓰지 않는다
- 한 장씩 빠르게 확인할 수 있어야 한다
- 상태 태그는 선택형이어야 한다
- 사용자는 글쓰기보다 정리에 집중한다

## 추천 화면 구조

```text
┌──────────────────────────────────┐
│  사진 1 / 3                      │
│  [ 사진 미리보기 ]               │
│                                  │
│  메모                            │
│  [ 누수 흔적이 보임            ] │
│                                  │
│  상태                            │
│  ( ) 정상  (•) 주의  ( ) 조치 필요│
│                                  │
│  [ 이전 ]        [ 다음 ]        │
└──────────────────────────────────┘
```

## 화면에서 보여줄 것
- 현재 사진 번호
- 사진 미리보기
- 짧은 메모 입력
- 상태 태그 선택
- 이전 / 다음 버튼

## 화면에서 숨길 것
- 긴 설명 입력
- AI 자동 채움
- 태그 과다
- 서식 설정

## 중요한 UX 포인트
- 메모는 한 줄 정도로 끝나도 된다
- 상태는 3개 이하가 적당하다
- 사진이 여러 장일 때도 반복이 편해야 한다
- 키보드를 열고 닫는 동작이 너무 많지 않아야 한다

## 다음 화면으로 이어지는 흐름
1. 사진마다 메모 입력
2. 상태 선택
3. 다음 사진으로 이동
4. 마지막 사진에서 템플릿 선택으로 이동

## 판단 기준
이 화면을 본 사용자가 아래를 즉시 이해해야 한다.
- 무엇을 적어야 하는지
- 어떤 상태를 고르는지
- 다음 사진으로 어떻게 넘어가는지

## 다음 액션

- 그 후 전체 흐름을 하나의 직선 플로우로 묶는다
